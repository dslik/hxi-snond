The tests for `is_valid_uuid` pass a null-terminated string and assert that the returned `bool` matches the expected validity. Because `is_valid_uuid` enforces three distinct conditions — string length equal to `C_UUID_STRLEN` (36), hyphens at byte offsets 8, 13, 18, and 23, and `isxdigit` acceptance at every other position — the six tests are chosen to exercise each condition independently. Test 1 confirms the happy path with a well-formed all-lowercase UUID. Test 2 confirms the happy path with a well-formed all-uppercase UUID. Tests 1 and 2 together verify that `isxdigit` accepts both letter cases. Test 3 exercises the boundary case of the RFC 4122 nil UUID, where every hex position holds a digit rather than a letter. Test 4 provides a 35-byte string to exercise the length check, which fires before any character inspection. Test 5 provides a 36-byte string with the non-hex character 'g' at offset 35 to exercise the `isxdigit` branch. Test 6 provides a 36-byte string with '0' at offset 8 instead of the required '-' to exercise the hyphen-placement branch. The tests for `generate_random_uuid` call the function with a caller-allocated buffer of `C_UUID_LEN` bytes and inspect the result. Test 1 verifies that the return value is 0 (C_SUCCESS), confirming the happy-path status. Test 2 passes the output buffer to `is_valid_uuid` and asserts that it returns true, confirming overall structural correctness. Test 3 checks that `strlen` of the output equals `C_UUID_STRLEN` (36), directly exercising the ENSURES postcondition of `generate_random_uuid`. Test 4 checks that the character at offset 14 of the output is '4': in the `snprintf` format string `"%02x%02x%02x%02x-%02x%02x-%02x%02x-..."`, bytes 0-3 occupy offsets 0-7, the first hyphen sits at offset 8, bytes 4-5 occupy offsets 9-12, the second hyphen sits at offset 13, and byte 6 begins at offset 14; because `generate_random_uuid` applies `uuid_bytes[6] = (uuid_bytes[6] & 0x0F) | 0x40U` before formatting, the high nibble of byte 6 is always 0x4 and the character at offset 14 is always '4'. Test 5 checks that the character at offset 19 is '8', '9', 'a', or 'b': the third hyphen sits at offset 18 and byte 8 begins at offset 19; because `generate_random_uuid` applies `uuid_bytes[8] = (uuid_bytes[8] & 0x3F) | 0x80U` before formatting, the high nibble of byte 8 is always 0x8, 0x9, 0xA, or 0xB, and the `%02x` directive produces '8', '9', 'a', or 'b' at offset 19. Six tests are provided for `is_valid_uuid` and five for `generate_random_uuid`, for a total of eleven tests. */ /* ## is_valid_uuid test 1 Tests that `is_valid_uuid` returns true for a well-formed all-lowercase UUID.
