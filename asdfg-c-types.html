They form the lowest layer of the conversion helper pattern required by rule 6.35, bridging between the C standard types (whose widths are platform-defined), POSIX types, and the fixed-width types from `<stdint.h>`. On the Linux target required by rule 11.1, `int` and `int32_t` are both 32-bit signed types with identical value ranges, and `long` and `int64_t` are both 64-bit signed types with identical value ranges. The REQUIRES range checks in `int32_from_int`, `int_from_int32`, `int64_from_long`, and `long_from_int64` are therefore always satisfied on that target. The checks are retained to make the valid input ranges explicit and to keep the functions portable to any future target where these type pairs have different widths. */ /* ## int32_t from int Converts a value of the platform-dependent C `int` type to the fixed-width `int32_t` type. The caller must ensure that the value is representable as a 32-bit signed integer. The function enforces this precondition with REQUIRES checks against `INT32_MIN` and `INT32_MAX` from `<stdint.h>`. ### Interactions | Parameter | Direction | Type | Description | | --------- | --------- | ------- | --------------------------------------------------------- | | input | in | int | The platform-dependent integer value to convert. | | return | out | int32_t | The input value as a fixed-width 32-bit signed integer. | Other changes to system state include: - None */ int32_t int32_from_int(int input) { int32_t result = 0; REQUIRES(input >= INT32_MIN, "input value is below the INT32_MIN bound"); REQUIRES(input <= INT32_MAX, "input value is above the INT32_MAX bound"); result = input; ENSURES(result == input, "Conversion did not preserve the integer value"); return(result); } /* ## int from int32_t Converts a value of the fixed-width `int32_t` type to the platform-dependent C `int` type.
