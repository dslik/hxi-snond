Each test exercises a single representative value and verifies that the conversion preserves it. The tests for `int32_from_int` call the function with a representative `int` value and assert that the returned `int32_t` holds the same value. Because `int32_t` and `int` have identical representations on the Linux target required by rule 11.1, integer constants such as `42` (which are of type `int`) are compared directly against `int32_t` results in the ASSERT conditions, following the same pattern used in the ENSURES check within the source functions under test. The tests for `int_from_int32` verify the round-trip property: an `int32_t` input converted to `int` by `int_from_int32` and immediately converted back to `int32_t` by `int32_from_int` must equal the original input. This approach avoids storing an `int` result in a local variable, which is not permitted by rules 6.17 and 6.18. Five tests are provided for each function, covering a typical positive value, zero, a typical negative value, the upper bound of the input type, and the lower bound. */ /* ## int32_from_int test 1 Tests that `int32_from_int` preserves a typical positive value.
